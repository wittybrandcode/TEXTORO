## 1) كيف يعمل TEXTORO اليوم مع النص؟ (تشريح دقيق من الكود)

النص مخزَّن في **ثلاثة أماكن** بأدوار مختلفة:

| # | المكان | المحتوى | من يقرؤه |
|---|---|---|---|
| S1 | `layer.comment` = `"TEXTORO_TEXT:" + نص` | نسخة الواجهة | `getLayerText` (تبويب Type)، Soga (`Utilities.jsx:806-817`) |
| S2 | Marker بتعليق `"TW_TEXT:" + نص` عند الزمن 0 | **نسخة الـ Expression** | تعبيرات sourceText v1.0/v1.3 (`sourceText.js:20-30`) |
| S3 | قيمة `Source Text` الثابتة للطبقة نفسها | تُكتب مرة واحدة عند التطبيق (`customText`) أو تبقى كما هي | **لا أحد في الرسم!** |

### تدفق الرسم الفعلي
```
Expression على خاصية Source Text:
   X  = قراءة TW_TEXT من markers      ← المصدر الوحيد للنص المعروض
   T  = floor(len(X) × progress/100)
   عرض = substr(X, 0, T) + cursor
```
**قيمة Source Text الثابتة (S3) لا تدخل في الحساب إطلاقًا.**

### مسار التعديل الحالي (عبر اللوحة فقط)
`updateLayerText` (`TypewriterManager.jsx:149-194`): إذا وجد Typewriter ⇒ يحدّث S1+S2 **ولا يلمس S3**؛ وإلا يكتب S3 مباشرة.

---

## 2) ماذا يحدث لو عدّلت النص من طبقة النص مباشرة اليوم؟

| الجانب | النتيجة الآن | التقييم |
|---|---|---|
| العرض على الشاشة | **لا يتغير شيء** — التعبير يعرض substring من TW_TEXT القديم | ❌ تعديل صامت مهمل |
| انهيار/خطأ | لا شيء ينكسر تقنيًا (التعبير لا يقرأ S3) | ✅ |
| لوحة Type/Soga عند الإعادة | تعرض النص **القديم** (تقرأ S1 أولًا) | ⚠️ حيرة مستخدم |
| طول الصندوق | يظل على مقاس النص القديم | ❌ |

> **خلاصة 2):** التعديل المباشر اليوم لا "يكسر" الإضافة، بل **يُتجاهل بصمت** — وهو أسوأ لأن المستخدم يعتقد أن التعديل تم.

## 3) واقع Essential Graphics / Mogrt (بحث خارجي)

**آلية العمل الرسمية (Adobe Help + Community):**
- تُسحب خاصية `Source Text` إلى لوحة Essential Graphics ⇒ تصبح قابلة للتحرير في Premiere.
- تحرير النص في Premiere (من EGP أو أداة النص) يعدّل **قيمة sourceText ما قبل التعبير**.
- التعبيرات تنجو داخل .mogrt وتُقيَّم في Premiere (مثال Adobe الرسمي: Dropdown Control مبني بالتعبيرات؛ توصياتهم باستخدام Slider/Checkbox Controls مع التعبيرات).
- `text.sourceText` يعيد محتوى النص (AE 17.0+ يعيد كائن Style إن طُلب `.style`).
- تحذير Adobe للأداء: التعبيرات الثقيلة تضر playback في Mogrt — تعبيراتنا (عمليات substring خفيفة) آمنة.

### الاستنتاج الحاسم للمشروع
```
في Premiere: المحرر يغيّر S3 (قيمة sourceText)
التعبير الحالي يعرض S2 (marker)  ⟹ تعديلات Premiere لن تظهر إطلاقًا
```
⟹ **بالبنية الحالية، تصدير Mogrt بنص قابل للتحرير غير عملي** — ليس بسبب قيد في Mogrt بل بسبب اختيارنا لتخزين النص في marker.

## 4) الحل المقترح: وضع Live Text (إصدار تعبير v1.4)

```javascript
// داخل تعبير Source Text — الفكرة كاملة:
var live = effect("Live Text")(1);            // Checkbox Control جديد
var X;
if (live == 1) {
    X = value.text;                            // S3: النص الحي قبل التعبير
} else {
    X = <قراءة TW_TEXT من markers كما اليوم>; // S2: النص المجمد
}
// ... بقية منطق القص/المؤشر/RTL دون تغيير
```

**لماذا يعمل هذا في البيئتين:**
- كلمة `value` داخل تعبير الخاصية تعيد قيمتها **ما قبل التعبير** — أي نص المستخدم الحقيقي في AE ونص المحرر في Premiere عبر EGP.
- نمط معتمد رسميًا (Adobe توصي بربط sourceText بعناصر تحكم/قراءة القيمة داخل التعبيرات لـ Mogrt).

### ما يتغير في المنتج
| المكوّن | التغيير |
|---|---|
| `expressions/typewriter/v1.4/sourceText.js` | نسخة جديدة بمفتاح Live Text (مع سلوك fallback آمن غياب الكنترول) |
| `_applyTypewriter` | إنشاء Checkbox Control باسم `Live Text` (افتراضي: مفعل للطبقات الجديدة) |
| Settings ⇄ Versions | تظهر v1.4 تلقائيًا (نظام الإصدارات موجود بعد F-06) |
| `updateLayerText` | يبقى كما هو — يمثل وضع "Locked" |
| `Soga/getLayerText` | عند Live=1 يقرأ S3 بدل S1 حتى لا تعرض اللوحة نصًا قديمًا |
| **مكسب إضافي** | يمكن كشف `TW Progress` و`Live Text` و`Blink Speed` في EGP ⇒ تحكم شامل من Premiere دون أي لوحة |

### المخاطر والحدود (بصراحة)
1. **حلقة ذاتية**: يجب استخدام `value.text` وليس `thisLayer.text.sourceText` داخل تعبير الخاصية نفسها (الأخيرة قد تعيد النتيجة المُقيَّمة). يُختبر أولًا على مشروع تجريبي.
2. **Multi-line**: Premiere يسمح بأسطر متعددة — منطق القص لدينا يقص بالنص كاملاً؛ يُضاف فحص `\r` في UAT.
3. **الطبقات القديمة**: تعبير v1.0/v1.3 يبقى لها؛ الترقية طوعية من Settings.
4. **Reverse + Live**: يعمل (النسبة تُطبَّق على الطول الجديد) — يُدرج في UAT.

### الجهد والتوقيت المقترح
| المرحلة | المحتوى | التقدير |
|---|---|---|
| N-04a | تعبير v1.4 + إنشاء الكنترول + فحص `value.text` | 3–4 س |
| N-04b | وعي اللوحة (Soga/Type يقرآن S3 عند Live) + UAT موسّع | 2–3 س |
| N-04c | سيناريو Mogrt كامل: تصدير → تحرير Premiere → Box يتتبع | 2–3 س |

**القرار المقترح:** اعتماد N-04 ضمن خطة **v1.1.0** (بعد بوابة v1.0.0)، لأنه يحوّل TEXTORO من "قالب AE" إلى "Mogrt احترافي جاهز للسوق".
